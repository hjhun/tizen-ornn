# Tizen Ornn 버전과 릴리즈

CLI와 GUI는 같은 제품 버전을 사용한다. 기본 형식은 `메이저.마이너.릴리즈`이며, 빌드를 구분할 때는 `1.1.0+vendor.2`처럼 선택적으로 `+문자열`을 붙일 수 있다. 문자열은 영문자, 숫자, 하이픈으로 구성된 식별자 하나 이상을 점으로 연결한다. 이 체계는 `1.0.0`부터 적용하며, 게스트 Tizen 플랫폼 버전과 독립적으로 관리한다.

| 변경 범위 | 올리는 자리 | 예시 |
| --- | --- | --- |
| 핵심 기능이나 사용 방식의 큰 변화 | 메이저 | `1.4.3 → 2.0.0` |
| 기존 기능을 유지하면서 새 기능 추가 | 마이너 | `1.4.3 → 1.5.0` |
| 버그 픽스, 문구 정정, 패키징 수정 등 단순 수정 | 릴리즈 | `1.4.3 → 1.4.4` |

한 배포에 여러 변경이 들어가면 가장 큰 변경에 맞춰 한 번 올리고, 그 아래 자리는 0으로 초기화한다.

## 배포할 때

공식 릴리즈의 제품 버전과 Git 태그에는 기존대로 세 숫자만 사용한다.

1. `config/version`과 `Cargo.toml`의 패키지 버전을 맞추고 `Cargo.lock`을 갱신한다. Cargo 빌드는 두 버전의 일치 여부를 검사한다.
2. 같은 커밋에서 Ubuntu와 Windows용 CLI·GUI를 빌드한다. CLI의 `--version` 출력과 GUI의 표시 버전을 확인한다.
3. 제품 버전과 같은 Git 태그(예: `1.0.0`)를 붙이고, GitHub Releases에 플랫폼별 패키지와 SHA-256 체크섬을 게시한다.
4. 같은 Ubuntu CLI·GUI 패키지로 APT 인덱스를 생성하고 기존 저장소 키로 서명한다. 공개 저장소에서 이전 버전의 두 패키지가 새 버전으로 업그레이드되는지 확인한다.

### Debian 패키지 버전

기존 Ubuntu 패키지 버전은 `29`였다. APT에서 `1.0.0`으로 정상 업그레이드되도록 Debian 패키지의 Version 필드에 epoch `1:`을 붙인다. 따라서 제품 버전 `1.0.0`은 APT에서 `1:1.0.0`으로 표시된다. 이후 배포에도 같은 epoch를 유지한다. GUI 패키지는 동일한 Debian 버전의 CLI에 의존한다.
